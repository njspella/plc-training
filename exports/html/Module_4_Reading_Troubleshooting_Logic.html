Lesson: Structured Troubleshooting Methodology

  • The 5-layer fault isolation model — a repeatable framework for diagnosis

Structured Troubleshooting Methodology (content)

  • Before diving into software tools, you need a systematic troubleshooting method. Random poking at the PLC wastes time. The 5-layer model isolates the fault location before you start fixing.
  • → The 5-Layer Fault Isolation Model
  • When something isn't working, the fault exists in one of five layers. Work through them in order:
  • • Physical Device — Is the field device itself working? Check sensor LEDs, listen for relay clicks, verify mechanical operation.
  • • Wiring — Is the signal getting from the device to the PLC? Check terminal block connections, measure voltage with a multimeter, verify wire continuity.
  • • I/O Module — Is the PLC module receiving/sending the signal? Check channel LEDs on the I/O card. A lit LED means the module sees the signal.
  • • PLC Logic — Is the program processing the signal correctly? Go online and trace the ladder rung. Is a contact preventing power flow? Is a timer stuck?
  • • Network/HMI — Is the information reaching the operator? Check HMI communication, verify tag mappings, confirm alarm configuration.
  • [INFO] Key Principle: Software tells you what the PLC thinks it sees. A multimeter tells you what's actually there. Always verify physical reality against software status. If they disagree, the truth is in the physical measurement.
  • → Half-Split Troubleshooting

Structured Troubleshooting Methodology (content)

  • Start at the midpoint of the signal path to halve your search space. If the I/O module LED is lit (layer 3 is good), the problem is either in logic (layer 4) or HMI (layer 5) — you've eliminated layers 1–3 in one check.

Lesson: Data Types & Tag Structure

  • Understanding BOOL, INT, REAL, and tag naming conventions

Data Types & Tag Structure (content)

  • Before reading tags in the I/O dashboard, you need to understand what you're looking at.
  • Table: Data Type | Description | Example
  • • BOOL | True/False, ON/OFF, 1/0 | Proximity sensor state, push button state
  • • INT (16-bit) | Whole number -32,768 to 32,767 | Counter values, small setpoints
  • • DINT (32-bit) | Whole number ±2.1 billion | High-speed counter values, encoder counts
  • • REAL (floating point) | Decimal numbers | Temperature (72.5°F), pressure (45.3 PSI)
  • • STRING | Text | HMI messages, recipe names
  • → Tag Naming Conventions
  • Good tag names follow a prefix-based convention that tells you the function area at a glance:
  • • SAFETY_EStop — safety function, E-stop circuit

Data Types & Tag Structure (content)

  • • MOTION_AxisHome — motion control, axis home position
  • • HMI_CycleStart — HMI-triggered, cycle start command
  • • CONV_ProxSensor1 — conveyor area, proximity sensor 1
  • → Global vs. Local Variables
  • A global variable is accessible from any program block in the PLC project. A local (program-scoped) variable is only visible within its own routine. Most I/O tags and inter-program signals should be global. Temporary calculation variables can be local.

Lesson: Reviewing Signals — Omron

  • I/O dashboard, variable monitoring, and live logic viewing in Sysmac Studio

Reviewing Signals — Omron (content)

  • → The I/O Dashboard
  • Open the I/O dashboard to see all input and output signals in a single view. Key columns:
  • • Node column: Which I/O node/module the signal is connected to. If blank, it's a global variable defined in logic.
  • • Variable name: The tag name used in the ladder logic
  • • Current value: Live value — TRUE/FALSE for BOOL, numeric for INT/REAL
  • → Live Logic Viewing
  • • Go to the Programs tab and expand it
  • • Double-click a program/routine to open the ladder logic editor
  • • Click the Monitor button (or toggle to online view) to see live values
  • • Contacts that are passing power show as highlighted/colored

Reviewing Signals — Omron (content)

  • • Contacts that are blocking power show as not highlighted
  • • Find the rung that is not working and identify which contact is blocking power flow
  • [TIP] Cross-Reference: Right-click any tag in Sysmac Studio and select Cross Reference to see every rung where that tag is used. Essential for understanding complex programs.

Lesson: Reviewing Signals — Allen Bradley

  • Monitor Tags, Tag Browser, and ladder logic tracing in Studio 5000

Reviewing Signals — Allen Bradley (content)

  • → I/O Configuration
  • In the Controller Organizer (left panel), expand I/O Configuration. Click any I/O module to view tag values mapped to that module. This shows you the physical layer — what the module is actually receiving.
  • → Monitor Tags
  • Go to Logic > Monitor Tags (or press Ctrl+W while online). The Tag Browser shows all tags with live values. Filter by name, data type, or scope.
  • → Tracing Ladder Logic
  • Open a routine and go online. Studio 5000 highlights the power flow through each rung in green. Work left to right on a rung to find which contact is blocking power (not highlighted). That contact's input condition is the one preventing the output from energizing.
  • → Forcing I/O
  • Right-click a tag in Monitor Tags and select Force ON or Force OFF. Forces override the physical signal — use with extreme caution.
  • [DANGER] Force Safety: Forcing an output ON bypasses all safety logic. Only force I/O for diagnostic purposes on a locked-out/safe machine. Always remove all forces when done — check the force indicator in the status bar. A forgotten force on a production machine can cause serious injury.

Lesson: Reviewing Signals — Productivity Suite

  • Data View, live monitoring, and signal tracing in Productivity Suite

Reviewing Signals — Productivity Suite (content)

  • → Data View
  • Go to View > Data View (or click the Data View tab at the bottom). This shows a live table of all tag values: I/O points, internal memory bits, timers, and counters. The "Current Value" column updates in real time — discrete inputs show 0 (off) or 1 (on).
  • → Signal Tracing
  • Open the ladder program and go online. Like the other platforms, power flow is visually highlighted. Identify blocked rungs by finding contacts that are not passing power, then investigate the associated physical device or upstream logic.
  • Toggle a physical device and confirm the value changes in Data View to verify signal continuity from the field through to the PLC.

Lab: Physical Input → Software Response

  • After: Structured Troubleshooting Methodology
  • Duration: 10 min
  • With the I/O dashboard open on the projected screen and the bench visible, have a student activate the proximity sensor. The class watches the tag change in real time.
  • Students take turns activating inputs while the class calls out which tag changed. Repeat with limit switch and push button. Then reverse — show an output tag and watch the physical device.

Lab: Force I/O — See It, Respect It

  • After: Reviewing Signals — Allen Bradley
  • Duration: 10 min
  • Force an output ON — students watch the light tower illuminate even though no logic commands it. Then force an input. Then remove forces and show normal operation.
  • Students observe the physical result of forcing. Trainer asks: 'What could go wrong if you force an output ON and forget?' Students locate the force indicator in each platform.

Lab: Planted Fault — Full Signal Trace

  • After: Reviewing Signals — Productivity Suite
  • Duration: 15 min
  • Trainer pre-plants a fault (disconnected proximity sensor wire). Walk through the 5-layer model live: check output → check logic → check input tag → check module LED → check wiring → find disconnected wire.
  • Students follow along and call out observations at each step. Guided walkthrough before independent scenarios in Module 7.

Quiz

  • A PLC input tag shows 0, but you measure 24VDC at the I/O module terminal with a multimeter. What layer has the fault?
  • Layer 1 — Physical Device | Layer 2 — Wiring | Layer 3 — I/O Module | Layer 4 — PLC Logic

Quiz

  • What does it mean when a contact is highlighted/colored in online ladder logic view?
  • The contact has an error | The contact is forcing the output OFF | The contact is passing power (its condition is TRUE) | The contact has been modified recently

Quiz

  • What is the danger of forgetting to remove a forced output?
  • It wastes PLC memory | It slows down the scan cycle | The output will stay ON regardless of safety logic, potentially causing injury | It corrupts the program file

Quiz

  • A REAL data type tag reads 72.5. What kind of value could this represent?
  • A Boolean state (ON/OFF) | A counter value | A temperature, pressure, or other continuous measurement | An error code
